# Feature Specification: Polymarket 自动化网格交易平台

**Feature Branch**: `001-polymarket-grid-bot`  
**Created**: 2025-10-31  
**Status**: Draft  
**Input**: 用户描述: "我想实现对于 polymarket 的一个自动化网格交易平台"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 启动可配置的网格策略 (Priority: P1)

作为交易者，我可以在 Polymarket 上选择一个市场与方向（Yes/No），设定价格区间、网格间距（tick/步长）、每格下单数量与预算上限，并一键启动自动化网格策略，系统会在订单簿上自动挂出初始网格并持续维护。

**Why this priority**: 这是最小可行产品的核心能力，直接产生交易行为和潜在收益。

**Independent Test**: 在任意单一市场、单一方向上，仅依靠该功能即可完成从配置到自动下单与维护的完整闭环。

**Acceptance Scenarios**:

1. **Given** 账户已连接且余额充足，**When** 用户设置区间、步长与每格数量并点击启动，**Then** 系统计算网格并在订单簿挂出对应数量的限价单。
2. **Given** 部分网格订单成交，**When** 系统检测到成交事件，**Then** 自动在对应价格层重新补挂订单以维持网格密度。
3. **Given** 价格越过边界，**When** 达到上/下边界，**Then** 按配置执行停机/扩展区间/仅被动撤单等策略行为。

---

### User Story 2 - 风险控制与资金保护 (Priority: P2)

作为交易者，我可以配置最大头寸/最大资金占用、单笔/当日亏损阈值、止损/止盈、成交冷却时间等风控参数，系统在运行中自动执行这些约束并给出可见的状态提示。

**Why this priority**: 保护资金与可持续运行，避免极端行情导致不可控风险。

**Independent Test**: 不依赖回测或其他模块，单独验证在实时或模拟行情中触发风控后的行为（撤单、停机、提示）。

**Acceptance Scenarios**:

1. **Given** 网格运行中，**When** 总资金占用达到上限，**Then** 系统停止新增挂单，仅维护既有订单或按策略撤减。
2. **Given** 当日累计亏损超过阈值，**When** 风控触发，**Then** 系统撤销全部未成交订单并暂停策略直至人工恢复。
3. **Given** 配置了止损价格，**When** 市价穿越止损阈值，**Then** 系统执行快速撤单并进入冷却期。

---

### User Story 3 - 模拟/纸面交易与回测 (Priority: P3)

作为交易者，我可以在不消耗真实资金的情况下进行纸面交易或基于历史成交数据进行快速回测，评估不同网格参数组合的表现，并导入为实盘配置。

**Why this priority**: 降低试错成本，帮助优化参数并提升策略信心。

**Independent Test**: 在无链上交互的前提下，基于历史或实时行情模拟成交与 PnL，输出可重复的绩效报告。

**Acceptance Scenarios**:

1. **Given** 选择历史时间区间与市场，**When** 运行回测，**Then** 产出收益率、年化、最大回撤、胜率、费用影响等指标报告。
2. **Given** 选择纸面交易模式，**When** 启动网格，**Then** 系统仅记录虚拟订单与成交，不产生链上交易并展示实时 PnL。

---

可按需扩展更多用户故事，例如多市场轮动、跨市场资金调度、通知/告警、参数热更新、多策略并行等。

### Edge Cases

- 市场流动性骤降：点差急剧拉大，订单长期无法成交或频繁部分成交。
- 手续费/滑点超预期：预估收益为负时应当暂停或调整网格密度与每格规模。
- 预言市场结算事件：市场状态从交易中转为结算/关闭，需自动撤单并结算持仓。
- 链路异常：Polygon/RPC 异常、签名失败、Allowance/Approval 未就绪导致下单失败的重试与降级。
- 价格数据异常：喂价延迟或跳变，防止“错误行情”触发风控或大量无效挂单。
- 账户余额不足：预算外下单被拒，需实时回退与提示。
- 部分成交与残单清理：长时间部分成交如何处理与重新布网。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001 市场与账户连接**: 系统必须获取 Polymarket 市场列表、订单簿快照/增量、账户余额与持仓信息。
- **FR-002 参数配置与校验**: 支持设置市场与方向、价格区间、网格步长、每格下单数量、总预算、时间在效(TIF)、补挂策略；参数需做边界与一致性校验。
- **FR-003 初始布网与下单**: 根据配置计算价格层级，批量创建限价单并记录订单与层级映射关系。
- **FR-004 成交监听与补挂**: 监听成交与撤单事件，自动在相应层级补挂，保持网格密度与库存平衡。
- **FR-005 风险控制**: 支持最大资金占用、最大头寸、当日亏损阈值、止损/止盈、冷却时间；违反规则时自动撤单/停机并提示。
- **FR-006 手续费与滑点**: 在下单与绩效统计中计入手续费；支持最小可接受成交价/滑点保护与失败重试策略。
- **FR-007 状态持久化**: 策略状态（网格层、未结订单、资金与仓位、风险状态）必须持久化，重启后可无损恢复。
- **FR-008 运行监控与日志**: 输出标准化日志、策略心跳、关键指标（PnL、资金占用、成交/撤单统计）；异常上报与本地告警。
- **FR-009 模拟/回测**: 纸面交易模式不产生链上交易；回测可读取历史成交或已导出的订单簿数据，输出绩效报表。
- **FR-010 多市场扩展(可选)**: 允许并行运行多个市场的网格策略，提供独立预算与风险隔离。
- **FR-011 认证与密钥管理（前端钱包签名）**: 系统永不在后端存储或接触钱包私钥。用户通过浏览器钱包（RainbowKit + wagmi）发起签名操作；前端调用 `@polymarket/clob-client` SDK 的 `createOrDeriveApiKey()`/`deriveApiKey()` 方法，使用浏览器钱包签名生成 API Key（`{ key, secret, passphrase }`）；生成的凭证存储在前端（会话内存或 sessionStorage），用于后续订单提交；支持 API Key 查看/吊销/重新派生的完整生命周期管理，所有操作需用户显式确认。
- **FR-012 交互模式与运行策略**: P1 阶段采用**交互模式**运行 — 用户在 UI 上配置网格参数并点击"启动"时，前端获得用户授权与 API Key，后端在预批准的额度上限（预算、头寸、风控规则）内自动执行下单与补挂，无需每单用户签名；策略停止、参数调整、风控触发等关键动作需用户明确确认。暂不支持"自主模式"（无人值守、后端自主签名持久化私钥的方案）。

_NEEDS CLARIFICATION_

- **FR-013 数据源**: 历史数据/实时数据的权威来源（官方 API、第三方数据集、私有节点）需确认与配额评估。

### Key Entities

- **Market(市场)**: 标识、方向(Yes/No)、最小变动价位、费率、状态(交易/结算)。
- **GridConfig(网格配置)**: 区间上下限、步长、每格数量、预算、TIF、补挂策略、风险参数。
- **GridLevel(网格层级)**: 价格层、目标订单数量、当前订单状态、最近成交信息。
- **Order(订单)**: 订单 ID、方向、价格、数量、状态、创建时间、关联 GridLevel。
- **Position(持仓)**: 方向、数量、均价、未实现/已实现 PnL。
- **Balance(余额)**: 账户 USDC/其它代币余额、Allowance、可用额度。
- **TradeEvent(成交事件)**: 订单事件、成交价量、时间戳。
- **RiskRule(风控规则)**: 阈值、当前状态、最近触发时间、处置动作。
- **StrategyState(策略状态)**: 运行模式(实盘/纸面/回测)、活跃市场、活跃层级、心跳与统计。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001 启动时长**: 从提交配置到全部初始网格订单成功挂出，95% 情况下 < 10 秒。
- **SC-002 稳定性**: 7×24 小时连续运行，订单失败率 < 0.5%，自动恢复成功率 > 99%。
- **SC-003 恢复能力**: 异常重启后，策略状态恢复到最新一致状态，数据丢失为 0，且恢复时间 < 5 秒。
- **SC-004 绩效度量**: 提供净值、年化、最大回撤、滑点与费率影响、胜率等指标，统计与导出准确率 100%。
- **SC-005 风控命中**: 当达到任一风控阈值时，100% 触发相应处置动作；误触发率 < 0.1%。
